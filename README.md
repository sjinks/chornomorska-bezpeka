# Часопис «Чорноморська Безпека». Севастопольський архів (2005—2013)

TypeScript + React + Bootstrap + Vite. Пошук працює локально в браузері по публічному знімку каталогу, без сервера й ключів Google.

## Запуск

Потрібні Node.js 20.19+ або 22.12+ та Python 3.

```sh
npm install
npm run data
npm run dev
```

Адреса: http://127.0.0.1:5173

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

`npm run typecheck` перевіряє типи застосунку, скриптів і тестів у строгому режимі. Збірка запускає цю перевірку автоматично. Скрипт підготовки даних і тести TypeScript виконуються через `tsx`.

Каталог `dist/` можна розмістити на статичному хостингу. Встановлені залежності зафіксовані у `package-lock.json`.

## Cloudflare Pages через GitHub Actions

Workflow `.github/workflows/cloudflare-pages.yml` використовує Node.js 24 і Python 3.13. Для pull request він встановлює залежності через `npm ci`, перевіряє ESLint і типи, перебудовує каталог із локального CSV, збирає сайт через Vite 8 та запускає тести. Готовий `dist/` зберігається як артефакт `site-dist` на 7 днів.

Після успішних перевірок push у `master` окреме завдання завантажує цей артефакт у Cloudflare Pages через Wrangler. Збірка виконується в GitHub Actions; Cloudflare отримує тільки файли `dist/`. Pull request не запускає розгортання. Workflow також можна запустити вручну; розгортання дозволене тільки для `master`.

Перед першим розгортанням:

1. Створіть у Cloudflare Pages проєкт **Direct Upload** із production-гілкою `master`. Вбудоване підключення Git для цього workflow не потрібне. Якщо основну гілку репозиторію перейменовано, змініть також trigger, умову завдання `deploy`, параметр `--branch` і production-гілку у Pages.
2. Створіть API-токен з дозволом **Account → Cloudflare Pages → Edit**, обмежений потрібним Cloudflare-акаунтом.
3. У GitHub відкрийте **Settings → Secrets and variables → Actions** і додайте:

| Тип                 | Назва                           | Значення                       |
| ------------------- | ------------------------------- | ------------------------------ |
| Repository secret   | `CLOUDFLARE_API_TOKEN`          | API-токен Cloudflare           |
| Repository secret   | `CLOUDFLARE_ACCOUNT_ID`         | ID Cloudflare-акаунта          |
| Repository variable | `CLOUDFLARE_PAGES_PROJECT_NAME` | Назва створеного проєкту Pages |

Після налаштування виконайте push у `master` або запустіть workflow вручну для цієї гілки. Якщо параметри відсутні, збірка пройде, а завдання розгортання повідомить, що потрібно додати. Підтримуйте CSV у Git: розгортання використовує локальний знімок, а не завантажує Google-таблицю.

Інструкція Cloudflare: [Direct Upload із CI](https://developers.cloudflare.com/pages/how-to/use-direct-upload-with-continuous-integration/).

## Розміщення в підкаталозі

Виконайте `npm run build` і завантажте **вміст** каталогу `dist/` у потрібний каталог сайту, наприклад `public_html/library/`. Відкривайте сайт за адресою `https://example.org/library/` (із завершальним `/`). Сервер має віддавати `index.html` як індексний файл каталогу; зазвичай це стандартне налаштування хостингу.

У збірці використовуються відносні шляхи до JavaScript, CSS і `catalog.json`, тому одна збірка працює як у корені сайту, так і в підкаталозі будь-якої глибини. Перебудовувати сайт для іншої назви каталогу не потрібно. Посилання з параметрами пошуку також залишаються в цьому каталозі. Спеціальні правила перенаправлення для SPA не потрібні, оскільки пошук використовує параметри URL, а не окремі маршрути.

## Оновлення каталогу та PDF

Для оновлення завантажте оригінальну Google-таблицю у форматі **XLSX**: CSV не зберігає кольорові позначки. Імпортуйте її та перебудуйте сайт:

```sh
python3 scripts/import_sheet.py /path/to/catalog.xlsx
npm run build
```

Імпортер читає перший аркуш з очікуваними заголовками каталогу. Зелені клітинки в колонці «Теги» задають додаткові пошукові зв’язки з авторами. Червоний текст у цій колонці задає додаткові рубрики. Інші кольорові позначки, зокрема нерозшифровані ініціали в колонці «Автор», не є пошуковими зв’язками. Імпортер зберігає ці позначки в явних колонках «Пошукові автори» і «Додаткові рубрики» локального CSV. За потреби ці колонки можна редагувати вручну. Зберігайте назви колонок. Колонка `PDF` містить повні HTTP(S)-посилання або порожні значення. Автоматична синхронізація не використовується.

Останній імпорт: 2026-11-18, з [вихідної Google-таблиці](https://docs.google.com/spreadsheets/d/1mD2QPdHERWU3qMURd2BhA1kajzlM7eAfkhoUKKNmako/edit?gid=0). Додаткові пошукові зв’язки позначено у 22 публікаціях, додаткові рубрики — у 7. Попередні варіанти імен і URL-ідентифікатори збережено. Нерозшифрованим лишається «Ісмаїлов Т.».

`link_authors.py` містить правила зіставлення імен і підтверджені пари різних людей. Додаткові пошукові імена не додаються до реквізитів статей. Лише явно позначені пошукові зв’язки використовуються для пошуку; непозначені імена в тегах не призначаються авторами автоматично. Записи з порожнім автором лишаються доступними за назвою, мовою та рубрикою. Непевні записи зберігаються в `author-linking/needs-review.csv`.

Пошук у назвах враховує всі введені слова в довільному порядку, без перекладу та морфологічного аналізу. Виберіть автора зі списку, впорядкованого за українським алфавітом, і натисніть «Знайти публікації». «Без автора» відбирає записи, в яких автор не зазначений. Бессарабов Олексій і його псевдонім Стрілецький Олексій доступні окремо у списку; вибір будь-якого з них знаходить публікації під обома іменами, зберігаючи початкову атрибуцію. Фільтр «Номер» показує наскрізний номер та рік, наприклад «28 (2013)». Раніше поширені посилання з фільтром року залишаються чинними. Фільтри поєднуються умовою «І» та зберігаються в URL. Імена авторів у видачі також працюють як фільтри. Запис без автора в реквізитах знаходиться одночасно за «Без автора» та за іменами з явно заданих пошукових зв’язків. Додаткові рубрики працюють разом з основною рубрикою і не замінюють її.

Ідентифікатори статей формуються з бібліографічних полів і залишаються незмінними при додаванні PDF або перестановці рядків. Після зміни назви, року, номера або сторінки ID зміниться; для майбутніх постійних сторінок статей варто додати явну колонку ID.

Вбудований PDF-переглядач і повнотекстовий пошук не входять у цю версію. PDF відкривається в новій вкладці. Усі дані `public/catalog.json` доступні відвідувачам.

Посилання на вихідну Google-таблицю прибрано з публічної навігації. Адміністратори користуються прямим посиланням; авторизації та адміністративної панелі на сайті немає.

## Обкладинки номерів

Оригінальні скани JPEG зберігаються в `covers/`. Сайт використовує готові оптимізовані копії з `public/covers/`; оригінали не потрапляють у `dist/`.

Оптимізовані обкладинки WebP зберігаються в `public/covers/`: `01.webp`–`28.webp`. Назва файлу відповідає колонці `(№)` з доповненням нулем до двох цифр. Зображення мають ширину 480 пікселів зі збереженням пропорцій. Vite використовує готові файли під час розробки та копіює їх у збірку без повторної обробки.

Галерея обкладинок дозволяє вибрати номер; решта активних фільтрів зберігається, фільтр року очищується, а сторінка результатів скидається на першу. Обкладинка вибраного номера показується над результатами. Для нового номера додайте відповідну оптимізовану обкладинку в `public/covers/`.

## Про часопис

Розділ «Про часопис» розгортається в потоці сторінки над галереєю номерів і згортається повторним натисканням заголовка або кнопкою «Згорнути». До отримання статті власника він містить повідомлення про підготовку тексту. Замініть цей текст у `src/AboutJournal.tsx`, коли стаття буде готова.
